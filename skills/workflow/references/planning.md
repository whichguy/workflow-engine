# Prompt entry and Backchain

Load this reference for a `planning` packet. The selected Backchain source checkout
owns planning instructions. Load its `skills/backchain/SKILL.md`, mandatory
`references/convergence.md` and full `references/technical-lenses.md`. Follow its
generator, dependency review, evidence resolution and elaboration procedure.
Do not copy an older version's review counter or stopping procedure into Weave.

The currently selected Backchain 0.3.4 delegates convergence to the actual selected
Until Loop skill and its package-relative ephemeral adapter. Resolve and read that
card and its adapter reference fully. The selected Until Loop owns recurrence,
recovery and terminal status; Weave and Backchain do not supply a parallel counter,
pass ceiling, or substitute scheduler. If that binding cannot be resolved, report
incomplete planning rather than silently using the former inline-review route.
Future versions remain governed by the selected card, not this version note.

Keep the exact original request as `plan.goal`. Put explicit commands, prompts,
outputs and checks in execution bindings keyed by Backchain step ID. Preserve
actual supplier relationships; DAG depth or `parallel_groups` does not establish
shared-write safety. Include every terminal deliverable and verification sink.
Consumed initial facts need real evidence through `_initial_evidence` bindings.

Retain the selected Backchain/Until Loop source identities, original request,
input/output candidate digests, exact terminal stdout receipt and domain evidence
in the selected Backchain companion format. The ephemeral child state is removed
at completion, so retain its actual receipt outside that state. Do not synthesize
a terminal receipt, infer convergence from packaging, or invent independent reviews.
With an explicit `backchain-caller/v1` packet use the source-aware route; otherwise
use compatibility-native. A source directory alone does not select source-aware.

The host checks that the selected planning procedure has completed and that its
receipt/evidence still belong to this candidate before invoking `accept-plan`.
The generic kernel validates structural packaging and execution bindings. It does
not receive or attest the semantic companion. This remains an explicit host
obligation; a separate experiment audits mechanical companion integrity without
making Until Loop policy a universal workflow-kernel requirement.

Keep structural artifacts, the planning companion and execution receipts distinct.
A receipt hash binds bytes; it does not prove semantic review quality or establish
who performed an external action. The accepted execution graph is frozen. Changed
requirements need an explicit new plan/run, not edits to accepted runtime state.
Improve retains its separate lifecycle and is not part of this planning binding.
